# GPU 时序 JEPA 实验

这个目录验证一个明确命题：先用 BTC 与 ETH 的大量**无方向标签**分钟行情学习市场状态表示，能否让 BTC 十分钟方向任务只用 1/3/6 个月标签就比手工特征和随机编码器适配得更好。

它不是 V-JEPA 2 的复刻，也不是完整的 LeCun 自主智能架构。它保留 JEPA 的关键机制：在线上下文编码器、无梯度 EMA 目标编码器、遮挡上下文、未来潜在表示预测，以及冻结表示后的少标签动作头。二元期权动作仍由显式 Planner 按 80% 净赔付在 `UP / DOWN / SKIP` 中选择。

## 严格边界

- 开发无标签预训练：BTC + ETH，2020-01-01 至 2024-12-31。
- 少标签训练历史：BTC，最早从 2024-01-01 开始，只为保证首个测试月也有完整 1/3/6/12 个月标签窗口。
- 少标签开发评估：BTC，2025-01-01 至 2026-01-31，逐月向前验证；2024 年不计入样本外成绩。
- 阈值选择：2025-01-01 至 2025-06-30，只在至少 300 笔的候选中按 PnL 选择 `min_ev`，平手取更低阈值。
- 开发确认：2025-07-01 至 2026-01-31，只用前段已选阈值评分，不反向参与选择。
- 最终冻结期：BTC，2026-02-01 至 2026-07-29。
- 开发阶段禁止读取冻结期方向标签或输出冻结期成绩。
- 只有开发阶段证明预训练表示优于随机编码器和手工 Logistic，且在 80% 赔付下为正，才允许固化方案并运行冻结期一次。
- 冻结期目标：胜率至少 58%、至少 300 笔、PnL 为正、多数月份为正，同时优于 Logistic 与随机编码器。失败必须原样报告，不能继续在同一冻结期调参。

“少数据”在这里指少量**有标签适配数据**。模型的市场先验来自约 688 万分钟无标签 BTC/ETH 数据，不是从一张样本或几天行情从零获得全部知识。

## 模型

- 480 分钟因果上下文，10 分钟一个 patch，共 48 个 token。
- 8 个无量纲通道：收益、实体、振幅、成交量变化、成交额变化、成交笔数变化、主动买入占比、绝对收益。
- 未来 10、30、60 分钟潜在目标。
- 4 层、128 维 Context Transformer；EMA Target Encoder；2 层 Predictor。
- CUDA AMP、AdamW、梯度累积、梯度裁剪、余弦学习率和原子 checkpoint 恢复。
- Predictor 与下游 context embedding 分别施加跨样本方差约束；context 另有维度相关性惩罚，防止 predictor 只靠资产 ID 和目标时距拟合平均状态。
- 表征诊断包括维度标准差、有效秩和平均两两余弦相似度。40 步真实数据复验中，validation loss 从 1.076 降至 0.514，有效秩从 10.0 升至 12.5，未出现修复前的近坍塌。

## 安装与完整性

当前已验证环境为 Python 3.11、PyTorch 2.5.1+cu121 和 RTX 3060 Laptop GPU。官方 wheel 通过独立 HTTP Range 分片获取，合并后精确为 2,449,385,544 字节，SHA-256 为 `4bcee18f00c43c815efad8efaa3bca584ffdc8d2cd35ef4c44c814f2739d9191`，与官方声明一致后才安装。不得使用禁用哈希或其他方式绕过完整性校验。

生产形状 CUDA AMP 基准中，batch 128 峰值显存约 239 MB，保留 batch 128、梯度累积 2（有效 batch 256）。完整测试覆盖 CUDA 前反向、EMA teacher、未来 patch、时间边界、checkpoint manifest、RNG 和中断恢复一致性。

安装成功后应首先验证：

```text
python benchmark_gpu.py
python -m unittest discover -s tests -t . -v
```

再运行：

```text
python run_pretrain_dev.py
python run_learning_curve.py
```

`run_pretrain_dev.py` 只训练开发 checkpoint；`run_learning_curve.py` 只使用 2025-01 至 2026-01 的开发标签。最终训练和冻结验收入口必须在开发门槛通过并生成锁定规格后才可执行。

## 生成文件

- `cache/*.npy`：内存映射行情通道、时间和收盘价。
- `checkpoints/dev.pt`：开发 JEPA checkpoint。
- `reports/dev_pretrain_report.json`：训练损失、吞吐、显存和坍塌诊断。
- `reports/learning_curve.json`：1/3/6/12 月标签的逐月样本外消融。
- `reports/gpu_benchmark.json`：真实 CUDA AMP 前向/反向吞吐与峰值显存。

缓存和 checkpoint 是本地派生大文件，不应作为源代码提交。实验不会修改或连接 `server.js`、`auto_btc.js`、实盘配置或下单逻辑。

## 正式开发结果

12,000 步开发预训练共处理 3,072,000 个无标签窗口。独立无标签 validation 的损失为 0.5393，embedding 平均维度标准差为 0.6208、最小维度标准差为 0.3534、有效秩为 30.10、平均两两余弦相似度为 0.2365，因此表示没有坍塌。

少标签学习曲线使用 2025-01 至 2025-06 选择固定 `min_ev`，再仅用所选阈值在 2025-07 至 2026-01 确认。1/3 个月少标签候选的确认结果如下；PnL 已按每笔 5 单位本金、赢得 4 单位、输掉 5 单位计算：

| 标签量 | 方法 | `min_ev` | 确认笔数 | 胜率 | PnL | 正收益月 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 1 月 | 手工特征 Logistic | 0.09 | 4,695 | 50.97% | -1,938 | 0/7 |
| 1 月 | 随机冻结 encoder + 线性头 | 0.09 | 10,515 | 50.23% | -5,037 | 0/7 |
| 1 月 | JEPA encoder + 线性头 | 0.09 | 10,124 | 51.71% | -3,505 | 0/7 |
| 1 月 | JEPA encoder + 两层 MLP | 0.09 | 15,628 | 51.48% | -5,726 | 0/7 |
| 3 月 | 手工特征 Logistic | 0.09 | 891 | 53.31% | -180 | 4/7 |
| 3 月 | 随机冻结 encoder + 线性头 | 0.09 | 1,708 | 49.82% | -881 | 1/7 |
| 3 月 | JEPA encoder + 线性头 | 0.09 | 2,490 | 52.53% | -678 | 1/7 |
| 3 月 | JEPA encoder + 两层 MLP | 0.09 | 9,954 | 51.10% | -3,996 | 0/7 |

JEPA 线性表示在部分少标签比较中优于随机 encoder，说明预训练并非完全无效，但所有 1/3 月 JEPA 候选都低于 80% 赔付对应的 55.56% 盈亏平衡胜率并产生负 PnL。两层 MLP 的校准和经济结果更差。12 月 JEPA 线性头在阈值选择期曾达到 725 笔、57.93%、PnL +155，但在独立确认期仅有 128 笔、55.47%、PnL -1，不能作为少标签或稳健正收益证据。

因此 `developmentGate.passed` 为 `false`。实验按预注册协议停止，不创建最终训练方案，不读取或运行 2026-02-01 之后的冻结期方向回测，也不据此继续调参。完整结果位于 `reports/learning_curve.json`。
