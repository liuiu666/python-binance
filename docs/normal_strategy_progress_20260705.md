# BTC 10分钟二元期权正态策略当前进度记录

生成时间: 2026-07-05

## 当前问题

用户核心要求不是“减少交易”或“简单停跑”，而是解决以下问题:

- 原始正态回归策略在部分天稳定，但遇到新价格区域/趋势延续时会连续亏损。
- 最大回撤曾达到 `39U`，不可接受。
- 现有趋势识别不够智能，容易把趋势突破误判成正态回归机会。
- 高频版本如果只放宽参数，交易次数会增加，但胜率和回撤明显恶化。
- 太保守版本虽然回撤低，但每天单数太少，不能满足需求。

## 已验证结论

### 大样本 balanced_dd21

本地有效数据: `2026-06-14` 至 `2026-07-04`

- 交易: `192` 单
- 胜率: `66.67%`
- 收益: `+192U`
- 最大回撤: `21U`
- 近段 `2026-06-29` 至 `2026-07-04`: `77` 单 / `66.23%` / `+74U` / 最大回撤 `21U`

核心规则:

- `r10 <= 42bps`
- `mid routeSigma < 20`
- `DOWN r10 <= 35bps`
- 数据覆盖阈值 `observed >= 88`
- 全局连续亏损控制: `2` 连亏后冷却 `3600s`

解释:

这版不是靠“看见趋势就全过滤”，而是承认正态回归会在某些趋势段失效，用连续亏损和波动区间状态识别“正态假设失败”。它目前是交易次数、胜率、回撤之间最平衡的版本。

## 为什么会亏

最大亏损不是单纯参数太松，而是行情从旧正态区间离开，形成新价格区域。策略仍按“极端点会回归”处理，导致连续反向。

危险特征:

- 中高波动切换段。
- `routeSigma` 约 `18-22`。
- `r10` 约 `35-45bps`。
- 连续回归失败。
- 价格沿上轨/下轨持续运行，也就是 band walk。

## 新学习到的外部交易依据

John Bollinger 官方规则明确指出:

- 触碰上轨/下轨本身不是买卖信号。
- 趋势市场中，价格可以沿着上轨或下轨持续运行。
- 带外收盘初期更像延续信号，而不是反转信号。
- 参数不是固定真理，不同市场/任务需要不同参数。
- 不应对价格分布做过强正态假设。

CFTC/SEC 对二元期权的风险提示:

- 二元期权是 yes/no 结算，亏损通常大于盈利。
- 若按本项目 `赢+4U / 输-5U`，盈亏平衡胜率约 `55.56%`。
- 所以策略不能只看胜率，还要看最大回撤、连续亏损、样本稳定性。

订单簿研究方向:

- 限价订单簿和 order-flow imbalance 对短周期中间价变化有解释力。
- 但当前本地订单簿覆盖率不足，暂时不能作为主触发，只能作为辅助过滤/解释。

## 下一步重新解决方向

不要继续写“出上轨就空、出下轨就多”的策略。

新策略应写成状态机:

1. `normal_reversion`: 正态回归可交易。
2. `trend_walk`: 价格沿轨运行，禁止逆势回归。
3. `transition`: 波动扩张但还没确认新区域，只允许更严格信号。
4. `failed_reversion`: 连续回归失败，冷却，等待滚动窗口重建新区间。
5. `resume`: 新区间稳定后恢复交易。

需要测试的特征:

- 10分钟滚动区间宽度 `r10`。
- 70分钟或180分钟 route sigma。
- bandwalk 连续贴轨次数。
- 突破后 5秒/15秒是否继续顺势推进。
- 到期前同向压力是否持续。
- 过去若干单是否连续失败。
- 数据覆盖率。
- 可用时叠加订单簿不平衡和微价格偏离。

验收标准:

- 本地回测，不在服务器跑。
- 训练/验证按时间切分，不能用未来数据。
- 报告每天交易次数、胜率、收益、最大回撤、连续亏损。
- 说明是否动态识别行情，不能只给固定参数。
- 不部署，除非用户明确要求。
