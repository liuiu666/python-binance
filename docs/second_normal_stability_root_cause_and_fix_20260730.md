# 秒级正态反转：根因与修复（2026-07-30）

## 最终根因

当前策略上线后亏损不是单一参数错误，而是四个问题叠加。

1. **回测优势小于真实执行误差。** V31 三月走步即时 `+7000U`，延后一分钟只剩 `+1313U`，收益衰减 81.2%；高波固定冠军从即时 `+1909U` 变成延后 `-1024U`。V28 再延后 10 秒也会翻负。
2. **优势发生年代漂移。** 三月走步延后口径在 2020–2023 合计 `+1764U`，2024–2026 合计 `-451U`。V36 加入 6.5 年 ETH 独立历史后，低波最好规则在 2024–2026 的延后结果也只剩 `+20U/3601单`。
3. **旧候选的样本和晋级门错误。** V13 的页面回测只有 264 小时、66 单，却曾使用“20 笔前向、63% 胜率”门槛；13/20 即使达到 65%，Wilson 95% 下限仍远低于盈亏平衡，不能证明稳定。
4. **线上模拟与配置曾不一致。** 旧配置中 V13 虽标为 shadow，却出现 `tradeEnabled=true` 且全局实盘开启；影子撮合又只检查信号是否过期，没有检查 actionable 时间是否已到，30 分钟影子单曾提前约 170 秒开仓，污染模拟结果。

另外，V13 的生产核心依赖秒级成交与订单簿，而多年历史只有分钟 OHLCV。V31–V37 能否定分钟级候选，却不能把一个不同的分钟模型冒充成 V13 的同代码长期回放。

## 已实施的本地修复

- `server.js` 新增统一的 `signalIsActionableNow` 防线；所有影子和服务器模拟路径，以及 `placeShadowTrade` 最终入口，都拒绝未来 actionable 时间和过期信号。
- `lib/trade_config.js` 强制所有 `shadowObservationRequired=true` 的 V9/V13 候选保持 `tradeEnabled=false`，即使配置误写为 true 也不能进入实盘策略集合。
- V13 冻结清单改为至少 500 个独立前向机会、胜率至少 60%、Wilson 95% 下限至少 57%、所有固定延迟盈利且延后 EV 至少保留 60%。
- 冻结 ETHUSDT Futures 3,417,120 个连续分钟，并完成 V36 固定规则和 V37 因果逐月模型；两轮均未通过。
- 当前线上只读核验为：`realTradingEnabled=false`、无 `tradeEnabled` 策略、V13 参数无差异。30 分钟候选虽已禁用且不会下单，但仍残留在配置中，因此“页面完全移除”尚未完成；本地管理器已把它列为必须删除的 retired 配置，本轮没有修改线上。

## 当前正确动作

低、中、高波全部 `no_trade`；V13 只保留影子观察，不允许实盘。这个动作解决的是“再次上线就亏”的资金安全问题，但没有伪造一个不存在的稳定盈利模型。

要证明可稳定交易，下一候选必须使用与生产完全相同的秒级核心，在连续逐笔/订单流数据上完成 0/5/10 秒及真实固定结算验证；Wilson 下限、年份、月份、相位和延迟保留率必须同时通过。否则继续调 Z、波动阈值或分类器只会放大过拟合。
