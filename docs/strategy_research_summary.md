# BTC 10分钟策略研究总结与上线参数

更新时间：2026-06-12

## 1. 名称说明

项目里当前的 `POCNormal` 名称容易误导。

- POC 的标准含义是 `Point of Control`，通常来自成交量分布/Volume Profile，表示某段区间成交最密集的价格。
- 本项目当前主策略不是严格的传统 POC。
- 当前主策略更准确的名字是：`Normal Tail Reversal`，即“正态尾部反转策略”。
- `OPC` 不是这里的正确名称。

保留代码里的 `poc_normal` 是为了兼容旧配置，但上线说明和模型标签应使用 `NormalTail`。

## 2. 主策略核心逻辑

主策略判断的是：最近一段价格收益率是否进入正态分布尾部，然后反向交易。

计算过程：

1. 使用 BTCUSDT 1分钟K线聚合成 2分钟K线。
2. 取最近 60分钟，也就是 30 根 2分钟K线。
3. 计算连续2分钟收盘价的对数收益率。
4. 估计均值 `mu` 和标准差 `sigma`。
5. 将收益率缩放到 10分钟期权到期窗口，即 5 根 2分钟K线。
6. 用正态分布计算上涨概率 `p_up`。
7. 反转交易：
   - `p_up >= 0.80`：短期偏涨过头，做 `DOWN`。
   - `p_up <= 0.20`：短期偏跌过头，做 `UP`。
8. 同一个策略触发后，30分钟内不再重复下单。
9. 当前上线版额外启用 taker 资金流同向过滤。

## 3. 当前上线版参数

当前生产主策略：`BTC_10min_NormalTail_2m_Gap30_TakerAlign`

| 参数 | 值 |
| --- | --- |
| 策略ID | `BTC_10min` |
| 期权到期 | 10分钟 |
| 数据源 | BTCUSDT 1分钟K线 |
| 聚合周期 | 2分钟 |
| 正态窗口 | 60分钟 |

## 4. 回测结果

### 4.1 不加 taker 的稳健主版本

版本：`safe_2m_gap30`

90天：

- 交易次数：332
- 胜率：63.86%
- 平均每天：约 3.7 笔
- 单日最多：8 笔
- 90分位单日交易数：6 笔
- 最大连亏：4

180天：

- 交易次数：629
- 胜率：61.84%
- 平均每天：约 3.5 笔
- 单日最多：9 笔
- 90分位单日交易数：6 笔
- 最大连亏：4

这个版本样本更完整，是低配置依赖的稳健基线。

### 4.2 taker资金流过滤版本

版本：`safe_2m_gap30_taker_align`

短样本结果：

- 交易次数：32
- 胜率：87.50%
- PnL：+99U
- 最大连亏：1

解释：

- `UP` 信号只在主动买盘占优时放行。
- `DOWN` 信号只在主动卖盘占优时放行。
- 胜率最高，但样本少，因为 taker 外部数据覆盖时间较短。

用户当前选择：直接启用该版本作为主策略。

## 5. 数据要求

实时运行至少需要：

- `data/btcusdt_1m.csv`
  - `open_time`
  - `open`
  - `high`
  - `low`
  - `close`
  - `volume`
- `data/btcusdt_taker.csv`
  - `timestamp`
  - `buySellRatio`
  - `buyVol`
  - `sellVol`

taker数据要求：

- 最近一条 taker 数据不能超过 30分钟。
- 如果 taker 文件缺失、字段缺失、为空、或数据过期，主策略不出实盘信号。
- 这样可以避免“没资金流数据也当通过”的错误。

## 6. 为什么用30分钟间隔

30分钟间隔不是 30分钟期权，也不是 30分钟K线。

它表示：

同一个 `BTC_10min` 策略下单后，接下来30分钟内不再开同策略新单。

原因：

- 正态尾部信号容易在同一段极端行情里连续出现。
- 连续开单会让多笔订单暴露在同一个市场环境中。
- 30分钟间隔能明显减少扎堆交易和连续亏损。

## 7. 资金配置

当前默认：

- `BTC_10min` 主策略：5U
- `BTC_30min` 暂停策略：1U

页面可以修改不同策略的默认投数。

当前关闭信心分档资金，避免金额被旧分档逻辑覆盖。后续如果重新启用分档，需要确认服务端、前端和 AutoJS 三端金额一致。

## 8. 不推荐上线的版本

以下版本暂不作为主策略：

- `aggressive_2m`：收益高，但交易过于集中，单日次数过高，最大连亏偏大。
- `daily_loss_stop2`：回测没有改善，反而拖累结果。
- `cap4`：硬限制每日次数后收益和胜率下降。
- 简单成交量/振幅过滤：在主参数上多数降低收益或交易质量。
- LS/资金费率过滤：样本敏感，暂不直接上线。

## 9. 后续优化方向

可以继续研究，但不应同时混进生产主策略：

1. taker阈值扫描：
   - 当前 `UP >= 1.05`，`DOWN <= 0.95`。
   - 可测试 `1.08/0.92`、`1.10/0.90`，观察胜率和交易次数。
2. 资金流窗口：
   - 当前使用最近一条可用 taker 数据。
   - 可测试最近 10分钟/15分钟平均 taker ratio。
3. 模型确认：
   - `safe_2m_gap30_ml62` 短样本胜率 72.66%，最大连亏 2。
   - 可作为后续二级确认，但不要和 taker 同时盲目叠加。
4. 独立实盘审计：
   - 每次信号记录 `p_up`、`taker_ratio`、过滤原因、下单结果。
   - 至少积累 100-200 笔后重新评估阈值。

## 10. 当前结论

当前按用户选择上线：

`BTC_10min = NormalTail 2m Gap30 TakerAlign`

这是最高胜率的资金流过滤版本。它的优势是胜率高、最大连亏低；主要风险是样本短。因此上线后必须保留严格数据检查和交易审计。
