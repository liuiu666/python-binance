# V30 逐笔订单流确认协议（订单流特征计算前冻结）

## 目的

V29证明单纯价格回收不能跨区间稳定。V30保持同一冻结分钟信号，仅使用前5秒逐笔主动买卖量判断是否真的出现卖方主动性。订单流字段此前未参与V14–V29的选择。

## 订单流定义

使用 Binance Futures `aggTrades`：

- `is_buyer_maker=false`：主动买入量；
- `is_buyer_maker=true`：主动卖出量；
- 前5秒不平衡：`(主动买量 - 主动卖量) / (主动买量 + 主动卖量)`。

DOWN信号期望卖方占优，因此数值越低越符合确认。

## 预注册规则

仅允许以下三个规则：

1. `flow_le_0`：前5秒订单流不平衡不高于0；
2. `flow_le_m0p2`：不平衡不高于-0.20；
3. `flow_le_0_and_price_reclaim`：不平衡不高于0，且5秒价格不高于信号时价格。

确认后测试额外0/5/10秒执行延迟；同时测试实际入场后600秒和固定原边界结算。

## 严格时间顺序

### 开发资格：2020–2022

规则只有同时满足以下条件才允许进入2023测试：

- 六档共同覆盖不少于50笔；
- 六档PnL全部为正；
- 六档胜率全部高于55.56%；
- 六档7日块bootstrap 90% EV下限全部大于0；
- 六档最大回撤不超过30U、最长连亏不超过3笔。

多个规则合格时，按六档中最差EV、最差Wilson下限排序；一个标准误内优先选择更简单且样本更多的 `flow_le_0`。

开发段没有合格规则时，V30直接输出 `no_trade`；后期结果只能报告，不能反向选择。

### 后续测试

若有开发合格规则：

- 2023六档必须全部PnL为正；
- 2024–2025重用验证六档必须全部PnL为正；
- 2023–2026合并共同覆盖不少于60笔；
- 六档Wilson下限全部高于55.56%；
- 六档至少3个年份为正、bootstrap下限为正、回撤不高于25U、连亏不超过3笔。

## 禁止事项

- 不新增订单流阈值；
- 不按2023以后结果改规则；
- 不改分钟信号、方向、z、窗口或持有期；
- 不部署、不更新影子路由、不启用实盘。
