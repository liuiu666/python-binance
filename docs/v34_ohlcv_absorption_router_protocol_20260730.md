# V34 分钟 OHLCV 吸收确认路由冻结协议（2026-07-30）

## 目的与证据边界

V31–V33 已否决单纯价格 Z、绝对结构门和自适应结构门。V34 不再修改波动、Z 或结构阈值，而是首次引入冻结分钟数据中尚未系统使用的独立信息：成交量、振幅、实体、上下影线和收盘位置，检验极值后的“吸收/拒绝”是否能把局部价格回归转化为可执行优势。

这些规则在 V34 结果运行前冻结；但设计发生在此前全历史研究之后，因此即使通过也只能是历史候选，不能把 2020–2026 重新宣称为全新留出集。

## 冻结数据和波动轴

- 使用相同的 3,458,880 分钟 BTCUSDT USD-M Futures 历史及两份 SHA-256 清单。
- 波动状态仍固定为过去 120 分钟收益波动，并用此前 7 天、滞后一期的 33%/67% 分位切分低/中/高。
- 不再增加平稳性/趋势状态轴；每个低/中/高状态直接比较所有冻结动作与空仓。

## 冻结基础动作

完全复用 V19 的 8 个 profile，不修改参数：

- 直接均值回归：`w60/z2.0`、`w120/z2.0`；
- 确认反转：`w60/z2.0`、`w120/z2.0`；
- 趋势延续：`w30/1.5`、`w60/1.5`；
- 趋势衰竭反转：`w60/2.0`、`w120/2.0`。

## 冻结 OHLCV 特征与确认规则

信号分钟使用已完成 K 线：

- `range = high - low`，并换算为开盘价基点；
- `body_fraction = |close-open| / range`；
- `lower_wick_fraction = (min(open,close)-low) / range`；
- `upper_wick_fraction = (high-max(open,close)) / range`；
- `close_location = (close-low) / range`；
- 成交量和振幅门使用此前 7 天、最少 3 天并 `shift(1)` 的 80% 分位，当前分钟不进入自己的门槛。

每个基础动作固定比较四种确认版本：

1. `ungated_control`：不加 OHLCV 门，仅作对照；
2. `directional_candle`：
   - 回归/确认反转/衰竭反转做 UP 时，阳线、下影占比 ≥ 0.35、收盘位置 ≥ 0.60；做 DOWN 镜像；
   - 趋势延续做 UP 时，阳线、实体占比 ≥ 0.50、收盘位置 ≥ 0.70；做 DOWN 镜像；
3. `volume_confirmed`：满足 `directional_candle`，且成交量达到过去 80% 分位；
4. `climactic_confirmed`：满足 `volume_confirmed`，且振幅达到过去 80% 分位。

共 8 × 4 = 32 个固定 profile；同一动作与确认版本必须由两个相邻基础窗口共同支持，不能靠单点晋级。

## 走步和通过门

- 信号只在整 10 分钟边界；训练窗为此前连续 3/6/12 个完整月，测试紧接的下一个月。
- 月末 purge 所有跨月结果，月初重置 10 分钟共享冷却。
- 同一信号共同评估 5/10/20 分钟 × 0/1 分钟延迟，以及延后 1 分钟但固定原 10 分钟结算点。
- 训练资格、Wilson、盈利月份、最差月、7 日块 bootstrap、相邻窗口支持和最终跨年份门完全复用 V32/V33，不放宽任何条件。
- 三种训练窗必须全部通过，才允许进入波动识别窗口敏感性和官方逐笔成交 0/5/10 秒验证；否则保持 `no_trade`。
