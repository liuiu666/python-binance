# V30 逐笔订单流确认结果（2026-07-30）

## 结论

三个预注册订单流确认规则在2020–2022开发段全部失败，`developmentSelection=null`，最终决策为 `no_trade`。

- 开发段146笔原信号中，各规则确认54至72笔，均达到50笔最低样本门，但没有任何规则的六档PnL、胜率、bootstrap、回撤和连亏同时合格。
- 最宽松的 `flow_le_0` 在开发段六档PnL为：实际入场后600秒 `-9/-36/-18U`，固定原边界 `+27/-9/0U`。
- 价格回收联合规则在2023–2026合并段确实出现六档全部盈利，但这是开发失败后看到的后期诊断，不能反向晋级；而且其六档仍未全部通过 Wilson 和连亏门。
- 本轮结果不能据此改阈值、只选某档延迟或只用2024年以后数据。

本轮只做本地历史研究，没有部署、没有更新影子路由或线上配置，也没有启用实盘。

## 订单流定义与冻结规则

信号后前5秒订单流不平衡定义为：

`(主动买量 - 主动卖量) / (主动买量 + 主动卖量)`

其中 Binance Futures `is_buyer_maker=false` 计为主动买量，`is_buyer_maker=true` 计为主动卖量。全部分钟信号均为 `DOWN`，所以数值越低表示卖方主动性越强。

只允许以下三个预注册规则：

1. `flow_le_0`：前5秒不平衡不高于0；
2. `flow_le_m0p2`：前5秒不平衡不高于-0.20；
3. `flow_le_0_and_price_reclaim`：不平衡不高于0，且5秒价格不高于信号时价格。

## 0/5/10秒执行口径

V30 的0/5/10秒是**完成前5秒确认后的额外延迟**：

- 确认后0秒：原信号后5秒入场；
- 确认后5秒：原信号后10秒入场；
- 确认后10秒：原信号后15秒入场。

每档同时使用两种结算语义：

1. `entry_plus_600s`：从实际入场tick起持有完整600秒；
2. `fixed_boundary`：统一在原信号时刻后600秒结算。

所以每个规则共有六个执行切片，所有门槛都要求六档共同满足，不能事后只选最好的一档。

## 预注册门槛

### 开发资格：2020–2022

规则必须同时满足：六档共同覆盖不少于50笔；六档PnL全部为正；六档胜率全部高于55.56%；六档7日块bootstrap 90% EV下限全部大于0；六档最大回撤不超过30U；六档最长连亏不超过3笔。

只有开发合格规则才允许按最差EV、最差Wilson下限和样本量排序并进入后续测试。开发段没有合格规则时，协议要求直接输出 `no_trade`。

### 后续测试门

若开发段产生候选，则还必须满足：2023六档PnL全部为正；2024–2025六档PnL全部为正；2023–2026合并共同覆盖不少于60笔；合并六档Wilson 95%下限全部高于55.56%；六档至少三个年份盈利、bootstrap下限为正、最大回撤不高于25U、最长连亏不超过3笔。

V30没有产生开发候选，因此后期数据只作诊断，不具备反向选择资格。
