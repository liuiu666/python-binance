## 纠偏后的目标

保留已经完成的CPU轻量原型作为对照组，不运行它的最终冻结集，也不删除其开发结果。新增 `world_model_lab/jepa_gpu/`，实现真正的“无标签大规模预训练 + 少量标签适配”的时序JEPA原型，并使用RTX 3060 Laptop GPU训练。

这里的少数据是指少量有标签适配数据，而不是从零只看少量市场数据就获得世界知识。模型先用约688万分钟无标签行情建立先验，再测试只给1/3/6/12个月BTC方向标签时是否能快速适配。

## 数据边界

### 无标签预训练

- BTCUSDT永续1分钟：3,458,880根。
- ETHUSDT永续1分钟：3,417,120根。
- 合计：6,876,000根完整分钟数据，均有manifest证明零缺口、零重复。
- 通道采用无量纲因果变量：log return、K线实体/振幅、log volume变化、成交笔数变化、taker buy share等；不输入绝对价格，促进BTC/ETH迁移。

### 开发协议

- JEPA开发预训练：BTC+ETH，2020-01至2024-12，无方向标签。
- 少样本开发评估：BTC 2025-01至2026-01，逐月向前验证。
- 每个测试月分别只使用此前最近1、3、6、12个月BTC标签训练动作头；标签窗口不会跨入测试月。
- 用2025-01至2026-01的完整样本外学习曲线选择标签窗口、动作阈值和固定架构。

### 最终冻结协议

- 方案选定后，用完全相同的固定训练配方重新预训练，允许使用截至2026-01-31的BTC+ETH无标签数据。
- 只用开发阶段选定的标签月数，训练截至2026-01-31的BTC动作头。
- 最终一次性验收仍为BTC 2026-02-01至2026-07-29。
- 现有程序曾计算该区间的候选数量和特征，但从未训练、选择参数或输出该区间成绩；报告标注为“逻辑隔离，非物理隔离”。GPU版设置独立冻结守卫。

## GPU模型

针对6GB显存采用约2–5百万参数的小型时序JEPA：

- 输入上下文：过去480分钟。
- Patch：每10分钟一个patch，共48个上下文token。
- 目标：未来10、30、60分钟对应的潜在表征；另加随机块遮挡以增强状态学习。
- Context encoder：4层Transformer，`d_model=128`、4头、FFN 256/384。
- Target encoder：context encoder的EMA副本，不接收梯度。
- Predictor：2层轻量Transformer/MLP，根据上下文表征、目标时间位置和资产ID预测目标潜在表示。
- 损失：归一化潜在表征上的Smooth-L1/余弦距离，并加入轻量方差约束防止表征坍塌。
- 训练：PyTorch CUDA、AMP混合精度、梯度累积、梯度裁剪；自动按6GB显存寻找安全batch，OOM时只降低batch，不改变模型与数据边界。
- checkpoint包含模型、优化器、EMA、配置和数据hash，支持中断续训。

这不是V-JEPA 2十亿参数复刻，而是遵循JEPA关键机制的金融时序实验：context encoder、EMA target encoder、潜在空间预测、遮挡/未来目标、无标签预训练。

## 少样本动作头与消融

冻结encoder后，在每个决策点提取市场状态embedding。每种标签量都训练同一套轻量头：

- 线性方向头：预测未来10分钟 `p_up`。
- 波动率/状态变化辅助头：预测未来波动桶，提高表征约束。
- Planner：按80%赔付比较UP、DOWN、SKIP，概率边际不足必须跳过。

同场比较四组：

1. 原始手工特征 + LogisticRegression；
2. 随机初始化但冻结的相同encoder + 线性头；
3. JEPA预训练encoder + 线性头；
4. JEPA预训练encoder + 小型两层MLP头。

只有第3/4组在1或3个月标签下优于第1/2组，才能证明预训练减少了标签需求；若只在12个月标签下有效，不称为强少样本能力。

## 验证门槛

先通过：

- GPU/AMP前向反向测试；
- 改变未来数据不改变当前输入测试；
- target encoder无梯度且只由EMA更新；
- 遮挡位置与未来目标正确；
- 训练/验证/冻结边界测试；
- checkpoint恢复确定性测试；
- 表征坍塌诊断（维度标准差、有效秩、embedding相似度）。

开发阶段需要看到：

- JEPA损失显著优于未训练基线；
- embedding没有坍塌；
- 预训练encoder在1/3/6/12个月学习曲线中优于随机encoder；
- 至少一个少样本窗口在2025开发OOF中优于原始逻辑回归，并在80%赔付下为正。

只有开发结果满足这些条件，才固化GPU版配置并运行最终冻结集一次。冻结目标仍是：胜率≥58%、至少300笔、PnL>0、多数月份为正、优于逻辑回归，并额外要求优于随机encoder消融。失败就明确报告未达到，不用同一冻结集继续调参。

## 实施顺序

1. 安装与当前驱动兼容的CUDA版PyTorch，验证RTX 3060可训练。
2. 建立GPU子目录、数据集与JEPA模型，先用小样本过拟合/坍塌测试验证实现。
3. 在2020–2024 BTC+ETH上运行开发预训练并保存checkpoint。
4. 提取embedding，运行1/3/6/12个月逐月少样本学习曲线和全部消融。
5. 审查开发结果；若无预训练增益，停止并判定该JEPA设计不合理，不运行冻结集。
6. 若有明确增益，固化架构、标签窗口和动作阈值；按同一配方预训练到2026-01，执行独立冻结验收一次。
7. 输出CPU浅层基线与GPU JEPA的对照结论，说明“少标签”究竟是否成立。

训练耗时取决于3060 Laptop的功耗和实际吞吐；实现会先基准测试，再按固定训练步数/窗口数报告真实耗时，不提前承诺结果或速度。
